## База знаний (Obsidian) — ОБЯЗАТЕЛЬНО К ПРОЧТЕНИЮ

Путь к vault: D:\Obsidian\Treiding
Читай через MCP-сервер obsidian-treiding (быстрее, чем Read/Glob по полному пути) — 
он подключён и видит этот vault. Если по какой-то причине недоступен — используй 
обычный Read/Glob tool по полному пути как запасной вариант.
Только чтение: не создавай, не редактируй, не удаляй файлы внутри D:\Obsidian\Treiding.

### Когда это правило действует

Перед ЛЮБЫМ из следующих действий — сначала прочитай Obsidian (см. порядок ниже):
- изменение парсинга CSV из TradingView (таймфрейм, направление, часовой пояс)
- изменение вкладок Аналитика/Разбивка/Сделки/Сравнение
- изменение режима баланса (реинвест/фикс), фильтров, тепловых карт, календаря-пивота
- изменение библиотеки бэктестов в localStorage, кривой капитала, сравнения стратегий
- любой рефакторинг index.html более чем в одном месте
- правка бага в отображении или расчётах

НЕ обязательно для: опечаток, чисто визуальных мелочей (цвет, отступ), тривиальных 
однострочных правок.

Если сомневаешься — считай, что правка большая, и читай Obsidian.

### Порядок действий перед большой правкой

1. Открой карточку проекта: D:\Obsidian\Treiding\Проекты\АнализаторБэктестов.md 
   (уточни точное имя файла через Glob, если не совпадёт)
2. Через Glob найди заметки с полем project: "[[...]]" (проект анализатора) и типом 
   "грабля" — прочитай пересекающиеся по теме
3. Аналогично найди открытые заметки типа "задача" по этому проекту
4. Только после этого предлагай/вноси изменения
5. Если натыкаешься на новую грабулю/задачу/смену статуса — НЕ создавай заметку сам, 
   сообщи об этом в чат текстом

### Критичные грабли (продублировано текстом)

- TradingView CSV-экспорты и графики по умолчанию в UTC+3 — учитывай это при 
  парсинге таймфрейма/дат, не предполагай UTC или локальное время пользователя
- Всё считается целиком в браузере (чистый HTML/CSS/JS, один файл index.html) — 
  никаких серверных вызовов; проверяй производительность на больших CSV
  прямо в браузере, а не абстрактно
- Хостинг — GitHub Pages: деплой занимает ~1 минуту, после публикации нужен 
  жёсткий рефреш (Ctrl+F5), иначе виден закэшированный старый JS/CSS
- Библиотека сохранённых бэктестов лежит в localStorage браузера — изменения 
  структуры данных в localStorage должны быть обратно совместимы со старыми 
  сохранёнными записями, иначе пользователь потеряет историю
- Метрики бэктеста считаются без комиссий и проскальзывания — если добавляешь 
  новую метрику или меняешь расчёт, явно отражай это допущение в UI/подсказках
